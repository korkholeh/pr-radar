## [MINOR] The refcounted large_scale_seed fixture does not actually share the seed — it still runs twice
`conftest.py`

`conftest.py:82` declares `large_scale_seed` with `scope="module"` and guards the seed with a session-scoped refcount, and DECISIONS (`p11-review_fix1`) records round 1's "two independent ~4-minute seeds" MINOR as fixed by it. Module-scoped fixture lifetimes never overlap: pytest finalizes a module's fixtures before the next module's setup, so the refcount goes 0→1→0→1→0 and the seed plus `reset_large_scale_data()` each run twice. Proven with `uv run pytest apps/dashboards/tests/test_seed_demo_scale.py tests/test_performance.py --setup-plan -q`, which prints `SETUP M large_scale_seed` / `TEARDOWN M large_scale_seed` / `SETUP M large_scale_seed` / `TEARDOWN M large_scale_seed`. The two consumers also sit in different directories, so they are never adjacent. Net effect: the ~8 minutes of gate wall-clock round 1 flagged is unchanged, and the plan's own "~3 minutes" bound is still exceeded.

**Fix:** Make `large_scale_seed` session-scoped so the second consumer reuses the cached value, and move the `reset_large_scale_data()` teardown to a `pytest_sessionfinish` hook (or an autouse session finalizer) to keep the "no later module sees 20,000 leftover rows" guarantee. Re-check with `--setup-plan`: only one SETUP/TEARDOWN pair should appear.

## [MINOR] The new overflow-x-auto wrapper silently kills the sticky table header
`apps/dashboards/templates/dashboards/partials/table.html`

`table.html:44` wraps the table in `<div class="overflow-x-auto">` (the e2e-driven fix for wide tables growing the page). Per CSS Overflow 3, when one axis is not `visible` the other computes from `visible` to `auto`, so that div becomes a scroll container on both axes and is now the nearest scrollport for the `sticky top-0` on the header row at line 47. The div's height is content-sized and never scrolls vertically, so the header no longer sticks as the page scrolls — on the People table (the one with enough rows to matter) the column headers scroll away. This is the only `sticky` in the whole template tree (`grep -rn sticky apps/*/templates templates`) and nothing tests it, so the regression is invisible to the suite.

**Fix:** Either drop `sticky top-0` from the header row (it no longer does anything, so keeping it is misleading), or restore the behaviour by giving the wrapper an explicit max height plus `overflow-y:auto` so it is a real vertical scrollport, and add an e2e assertion that the header stays in view after scrolling the People table.
