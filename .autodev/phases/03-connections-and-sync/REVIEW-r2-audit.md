## [MINOR] repository_rebind still calls GitHub when validation already failed
`apps/connections/views.py`

The r2 fix for major #2 says to "skip the discovery call entirely when `error` is already set", but views.py:284 calls `_discover_nodes(connection)` unconditionally. On the missing-`confirm` path (views.py:275) `error` is already the "Tick the confirmation box" message, yet a full paginated repositories query still goes out to GitHub before the fragment is rendered, burning rate budget on a request that changed nothing. The `error = error or ...` guard means the GitHub failure message is correctly suppressed in favour of the validation message, so this is cost, not a wrong response — the no-500 requirement the finding was about does hold, and test_rebind_without_confirm_does_not_move_repository still passes.

**Fix:** Wrap the `_discover_nodes` call in `if error is None:` so a rebind rejected for a missing confirmation renders the fragment from the existing state without a GitHub round-trip.
