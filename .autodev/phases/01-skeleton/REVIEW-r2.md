# Review — phase 1 round 2

**Verdict:** changes_requested

Phase 1 is in good shape: I ran every gate myself and all are green — `uv run pytest -q` (108 passed, including from a clean `git archive` copy that has no `.mo` files), the full lint chain, a fresh Tailwind build byte-identical to the committed `static/css/app.css` with a matching `.build-manifest.sha256`, and a full `make e2e-up && uv run pytest e2e -q; make e2e-down` round trip (4 specs, no leaked processes, `.e2e/` removed). Every r1 blocker/major is really fixed and the fixes are the right ones, not papered over: `.mo` compiled from `conftest.py`, `HUEY.immediate` set on the real `djhuey` singleton with a test that a task runs inline, pragma tests that call `config.db.apply_sqlite_pragmas` and query `django.db.connection`, `STORAGES` replacing the no-op `STATICFILES_STORAGE` plus a prod `SECRET_KEY` that fails fast, a checksum-based CSS staleness guard that can actually fail, and JS i18n routed through `/jsi18n/` with a populated `djangojs.po`. Each acceptance criterion has a test that maps to it. One major remains: the r1 blocker fix made the test suite self-sufficient but not the shipped app — on a clean install `.mo` files are never built, so the Ukrainian UI silently falls back to English, and no gate notices because the tests compile their own catalogues. Three minors round it out.

## [MAJOR] Ukrainian UI is dead on a clean install: nothing in the install path compiles the .mo catalogues
`docs/SETUP.md`

`.gitignore:5` ignores `*.mo` and only the `.po` files are tracked. Three things compile them: `make messages`, `make e2e-up`, and the new session-scoped `_compiled_uk_catalogs` fixture in `conftest.py`. None of them is on the operator's path — `docs/SETUP.md` "Install" is `uv sync` + `cp .env.example .env` + `migrate`, and README points straight at it. Proven on a clean tree (`git archive HEAD | tar -x -C /tmp/cleanco2` + the staged diff, no `.mo` present): `DJANGO_SETTINGS_MODULE=config.settings.local python -c "...translation.override('uk'); gettext('Overview')"` → `Overview -> Overview` (while `Log in -> Увійти` only because Django's own bundled catalogue happens to cover it). So a user who installs per SETUP.md and picks Ukrainian from the switcher gets an English page, which is exactly what the phase goal ("bilingual") and the acceptance criterion "switching language flips a page to uk" promise. The gate cannot catch this: the r1 blocker fix made `conftest.py` build the artifact the shipped app lacks, so `tests/test_translations.py` now proves the `.po` files, not the running product. `docs/SETUP.md`'s "Translations" section mentions `make messages`, but frames it as the workflow for *adding* a string, not as an install step — and `make messages` additionally needs `xgettext`/`msgmerge` on PATH, which the Install section never states as a requirement.

**Fix:** Add the compile step to `docs/SETUP.md` Install (and the README quickstart): `uv run python manage.py compilemessages -l uk --ignore=.venv`, with a note that it needs GNU gettext's `msgfmt` installed. Preferred alternative, consistent with how `static/css/app.css` is handled: commit `locale/uk/LC_MESSAGES/*.mo` (drop `*.mo` from `.gitignore`) and add a freshness test asserting each `.mo` is newer than and consistent with its `.po`, so the shipped artifact is the one the tests check.

## [MINOR] CSS staleness checksum covers every .py under apps/, so unrelated Python edits force a `make css` rerun
`scripts/css_manifest.py`

`_scanned_files()` hashes `tokens.css`, `src/input.css` and every `.html`/`.py`/`.js` under `templates/`, `apps/` and `static/js/` — including `apps/*/migrations/*.py` and `apps/*/tests/*.py`. From phase 2 on, adding a model, a migration or a single test will fail `tests/test_css_tokens.py::test_app_css_is_not_stale` with "static/css/app.css is stale — run `make css`" even though no class name changed. Rebuilding then requires the Tailwind standalone binary, which `make css` downloads from GitHub into `.tools/` on a clean machine — an unrelated network dependency on the way to a green build — and rewrites `.build-manifest.sha256` in every commit. The guard is correct (it mirrors `@source "../../../apps"`), just aimed wider than the actual sources of class names.

**Fix:** Narrow both the `@source` directives in `static/css/src/input.css` and `SCAN_DIRS`/`SCAN_SUFFIXES` here to the files that can actually contain utility classes — `templates/`, `apps/*/templates/`, `static/js/` — or keep `apps/**/*.py` but exclude `migrations/` and `tests/` from both.

## [MINOR] A URL that cannot be reversed is silently dropped from the deny-by-default parametrization
`tests/test_urls_login.py`

`_reverse()` (lines 37-45) swallows every exception with two bare `except Exception: pass`, and `ALL_NAMED_URLS` (line 48) then filters out anything that returned `None`. The recursive walk fixed in r1 will find a future URL such as `projects:detail` with a `pk` argument, `_reverse` will fail on both attempts because `SAMPLE_ARGS` has no `pk`, and the URL disappears from the only test that enforces "every URL redirects an anonymous user to login" — with no warning, no skip marker, nothing in the `-q` output. This is the one check that keeps acceptance criterion 3 true as the URL surface grows in phases 2-9.

**Fix:** Collect the unreversible names into a module-level list and add a test asserting it is empty (message: "add sample args for <name> to SAMPLE_ARGS"), or emit them as `pytest.param(..., marks=pytest.mark.xfail(strict=True))` so they stay visible in the report.

## [MINOR] `text-white` on `bg-[var(--accent)]` is a colour outside the token system and fails AA in dark mode
`apps/accounts/templates/registration/login.html`

`login.html:27`, `password_reset_form.html:16` and `password_reset_confirm.html:22` all render the primary button as `bg-[var(--accent)] px-4 py-2 text-white`. `text-white` is a Tailwind palette literal, so it is invisible to `tests/test_no_hardcoded_colors.py` (which only greps `#hex`/`rgb(`/`hsl(`), yet it is a hardcoded colour in exactly the sense CLAUDE.md forbids. In dark mode `--accent` is `#6ea8fe`; white text on it is ~2.4:1, below the 4.5:1 WCAG AA threshold for normal text — while PLAN.md claims "AA contrast in both themes". Full contrast work is phase 11, but this token gap is introduced here and will be copied by every button added in phases 2-9.

**Fix:** Add an `--on-accent` token to `static/css/tokens.css` with a per-theme value that clears 4.5:1 against `--accent` (e.g. `#ffffff` light, `#0f1115` dark), use `text-[var(--on-accent)]` in the three templates, and extend the colour-literal test's regex to reject Tailwind palette colour classes (`text-white`, `bg-gray-500`, …) in templates.
