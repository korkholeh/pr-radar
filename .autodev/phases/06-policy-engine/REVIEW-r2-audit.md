## [MINOR] First policy version saved before the first sync still governs no history
`apps/policy/services.py`

save_policy_version falls back to timezone.now() when PullRequest.objects is empty — exactly the fallback the round-2 review prescribed. But Settings → AI policy is reachable before any sync, so a lead who configures the policy first and syncs six months of history afterwards hits the same user-visible failure the major finding described: every synced PR predates effective_from, _policy_at returns None for all of them, and the Policy console stays permanently empty. The same holds for a repository added after the first save, whose historical PRs all predate it. docs/POLICY.md and docs/user/handle-policy-violations.md describe this accurately ('every pull request already synced'), and recompute cannot widen an existing version, so the only remedy is /admin/. Not raised as a blocker because the diff implements the review's own instruction verbatim.

**Fix:** Later phase: when the earliest PullRequest.created_at is before the oldest AIPolicy.effective_from and only one version exists, either widen that version's effective_from during recompute or surface a one-click 'apply the first policy version to already-synced history' action on the settings page. Log whichever is chosen as a decision.

## [MINOR] View-to-form scoped-queryset wiring has no test
`apps/policy/views.py`

projects_in_scope/repositories_in_scope have their own scoping tests, but nothing asserts that _filter_form actually passes them into ViolationFilterForm, so a future refactor could drop the kwargs and re-introduce the unscoped dropdown without failing the suite. Harmless today (scope_for_user is unrestricted until phase 9) and the fix itself is correct.

**Fix:** Add one console test that, with a restricted ScopeFilter, asserts the rendered project/repository <select> options contain only the in-scope names — most naturally once phase 9 makes scope_for_user narrow for real.
