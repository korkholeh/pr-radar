## [MINOR] A checkbox-less AI section no longer ends at a bold heading or `---`, so a later section's ticks leak in
`apps/ai_detection/disclosure.py`

`_find_section` (disclosure.py:126-140) only honours the soft boundary once `seen_checkbox` is true. When the AI-assistance section itself contains no checkbox — free text, a placeholder comment, a malformed template — a following bold-headed or HR-delimited section is no longer a boundary, and its ticks are read as the AI disclosure. Verified shapes: `### AI assistance\n<!-- pick one -->\n\n**Checklist**\n- [x] Tests added\n- [x] Docs updated\n` yielded MISSING before the fix, now yields AMBIGUOUS; `### AI assistance\n\n---\n\n**Checklist**\n- [x] ...` likewise. Blast radius is small: SPEC.md:265 fires `DISCLOSURE_MISSING` on `ai_disclosure ∈ {missing, ambiguous}` and SPEC.md:307 counts both as non-valid disclosure, so policy and `disclosure_rate` are unchanged. A genuinely wrong per-person value needs the leaked section to contain exactly one tick whose label starts with a configured synonym (defaults `None` / `Partial` / `Substantial`) — e.g. a checklist item `- [x] None of the migrations are destructive` would store `ai_disclosure=none` for a PR that disclosed nothing. ATX-headed sections (the common template shape) are unaffected, since they stay hard boundaries. No test covers a checkbox-less AI section followed by a bold/HR-delimited one.

**Fix:** Also end the section at a soft boundary when the section has produced any non-blank content since `content_start` (track `seen_content`, not only `seen_checkbox`), and exempt only the still-empty run of blank lines and instruction text that precedes the first checkbox — or, more simply, treat a soft boundary as terminal once either a checkbox or a previously seen soft boundary has been passed. Add the two bodies above as regression tests asserting MISSING.
