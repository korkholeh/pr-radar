One app per bounded piece of the domain. Views stay thin: validate input, call a service, render a template.
Business rules live in `services.py`; queries live in `selectors.py` and **always start from a `ScopeFilter`**
(ADR 0002), never from `Model.objects.all()`.

## Commands

All run from the repository root. All are non-interactive.

| Key | Command |
|---|---|
| install | `uv sync` |
| test | `uv run pytest -q` |
| lint | `uv run ruff check . && uv run ruff format --check . && uv run mypy && uv run python manage.py makemigrations --check --dry-run && uv run python manage.py check` |
| format | `uv run ruff format .` |
| run | `uv run python manage.py runserver 8000` |
| worker | `uv run python manage.py run_huey` |
| e2e up | `make e2e-up` |
| e2e | `uv run pytest e2e -q` |
| e2e down | `make e2e-down` |
| css | `make css` — then **commit `static/css/app.css`** |
| translations | `make messages` — `makemessages -l uk -a` + `compilemessages` |

### What the gate commands assume (phase 0 must make these true)

- `[tool.pytest.ini_options]` in `pyproject.toml` sets `DJANGO_SETTINGS_MODULE = "config.settings.local"`,
  `testpaths = ["apps", "tests"]` (so the bare `pytest` gate does **not** pick up `e2e/`), and
  `addopts = "-q --strict-markers"`.
- `[tool.mypy]` sets `files` to the typed surface only — spec §12 asks for `services/` and `metrics/`:
  `files = ["apps/metrics", "apps/*/services.py", "apps/*/selectors.py", "apps/*/services"]`,
  plus `plugins = ["mypy_django_plugin.main"]` and `mypy_path`/`django_settings_module` for
  `django-stubs`. That is why the lint command can be a bare `uv run mypy`.
- `manage.py` defaults `DJANGO_SETTINGS_MODULE` to `config.settings.local`.
- `makemigrations --check --dry-run` is part of lint on purpose: a model change with no migration fails the build.

### Makefile targets phase 0 must create

```make
E2E_PORT ?= 8100
E2E_ENV  = DJANGO_SETTINGS_MODULE=config.settings.e2e

e2e-up:            ## migrate, seed, collectstatic, start server + worker in background, wait for ready
	$(E2E_ENV) uv run python manage.py migrate --noinput
	$(E2E_ENV) uv run python manage.py seed_e2e
	$(E2E_ENV) uv run python manage.py collectstatic --noinput
	$(E2E_ENV) uv run python manage.py compilemessages
	uv run playwright install chromium
	$(E2E_ENV) nohup uv run python manage.py run_huey  > .e2e/huey.log  2>&1 & echo $$! > .e2e/huey.pid
	$(E2E_ENV) nohup uv run python manage.py runserver $(E2E_PORT) --noreload > .e2e/web.log 2>&1 & echo $$! > .e2e/web.pid
	# block until the port answers, then return; fail after 45s
	uv run python -c "import socket,sys,time; [ ... poll 127.0.0.1:$(E2E_PORT) ... ]"

e2e-down:          ## kill by pidfile, tolerate already-dead
	-kill `cat .e2e/web.pid .e2e/huey.pid 2>/dev/null` 2>/dev/null; rm -rf .e2e
```

`make e2e-up` **must return once the port answers** — the readiness poll is not optional. `.e2e/` is git-ignored.

## Stack specifics

### htmx
- Every htmx endpoint returns a **fragment**; the same URL returns a full page for a normal request, chosen by
  `HX-Request`. The convention is written once in `docs/dev/architecture.md`.
- Name the swap target and the trigger explicitly; never rely on the default swap.
- Errors must return a **visible** fragment. An HTTP 400 with an empty body swaps nothing and looks like a frozen
  button.
- CSRF token set once in `base.html` via `hx-headers`.
- Anything that changes data is POST/PUT/DELETE, never GET.

### Themes and CSS (ADR 0008)
- Colour literals (`#hex`, `rgb(`) are allowed **only** in `static/css/tokens.css`. A test greps for violations.
- Dark mode is bound to `[data-theme="dark"]`, not to `prefers-color-scheme`. The server writes `data-theme` on
  `<html>`; one tiny inline script in `<head>` resolves System mode before first paint.
- `static/css/app.css` is generated and committed. After changing templates, run `make css` and commit the result.
- `charts.js` reads colours with `getComputedStyle` and redraws on `themechange`.

### i18n (spec §10.7)
- New UI strings get their Ukrainian translation **in the same phase**, not later.
- System-generated text (violations, connection-check results, sync errors) is stored as a code + params and
  rendered in the reader's language. Never store a rendered English message.
- Never concatenate translated fragments; full sentences with named placeholders only. Plurals always `ngettext`.
- `.po` committed, `.mo` built by `make messages`.

### Secrets (ADR 0004)
- The `SecretMaskingFilter` on the root logger is created in **phase 0**, before any token exists.
- Never put a token in a URL, a log, an exception, `SyncRun.error_log`, a template, the Django admin, an export,
  or a subprocess argument. `git` gets it via `GIT_ASKPASS` + env only.

### GitHub (intake constraint — non-negotiable)
- **No live GitHub API call at any point in this run.** All behaviour is exercised against JSON fixtures in
  `tests/fixtures/github/`, mocked with `respx`. Tests must fail loudly if a real request escapes — install a
  `respx` assert-all-mocked default in `conftest.py`.

## End-to-end

Playwright against the server `make e2e-up` started, with `DEBUG=False` (`config.settings.e2e`) so a real 500
shows as a real error page. Seed only through `manage.py seed_e2e` — never write to the database behind the app's
back. Cases worth having here:

- a form that fails validation and shows field errors **in the swapped fragment**;
- a partial update (violation acknowledge, sync trigger) that leaves the rest of the page intact;
- the browser Back button after several htmx swaps, with filter state restored from the query string;
- one page per role: `admin` sees Settings, `lead` gets 403;
- a restricted `lead` seeing neither another project's page nor its chart JSON nor its CSV/XLSX export;
- the theme switch persisting across a reload and a new session, with no flash;
- the language switch flipping a page to `uk` and back.

## Pitfalls specific to this project

- `DEBUG=True` hides real 500s. e2e runs `config.settings.e2e` with `DEBUG=False`.
- N+1 queries hide in templates. Assert query counts (`assertNumQueries`) on every list view — this is also
  risk #10.
- A median of daily medians is wrong. Only additive metrics go into `DailyRollup` (ADR 0007).
- Day boundaries are `Europe/Kyiv`, not UTC. One helper owns them; test the DST transition.
- SQLite has one writer. The queue is a **separate** database file; never point huey at `db.sqlite3`.
- Generated files in the repository go stale: `static/css/app.css`, `docs/METRICS.md`, `locale/**/*.po`. Each has
  a freshness test.
- `pytest` must not collect `e2e/` — it needs a running server. `testpaths` excludes it.
